## 4. Encryption, signatures and custody

| Element | Design |
|---|---|
| Setup | Generate encryption keypair and Ed25519 signing keypair. Site retains encryption public key and protected signing secret; doctor's offline, versioned key bundle holds encryption private/public key and signing public key, key IDs and format. The signing secret is deliberately host-resident under D-C, not included in backups. **Salt, nonce and AEAD:** while the backup archive payload uses `secretstream` (which manages its own internal stream nonces; see `Backup` below), the offline key bundle is encrypted as a single AEAD message: each bundle creation or key rotation generates a **fresh random salt** (`SODIUM_CRYPTO_PWHASH_SALTBYTES` = 16 bytes via `random_bytes()`, never reused across bundles) and derives a unique 256-bit wrapping key from the independently held recovery phrase with Argon2id (`SODIUM_CRYPTO_PWHASH_ALG_ARGON2ID13`; [PHP `sodium_crypto_pwhash`](https://www.php.net/manual/en/function.sodium-crypto-pwhash.php)). **PROPOSAL — Argon2id header bounds (INFERENCE, pending owner confirmation):** the bundle cleartext header stores explicit integer `alg`, `opslimit` and `memlimit`, bound in AEAD additional data; proposed bundle default is `SODIUM_CRYPTO_PWHASH_OPSLIMIT_MODERATE` and `SODIUM_CRYPTO_PWHASH_MEMLIMIT_MODERATE` (256 MiB in current libsodium), with floor `SODIUM_CRYPTO_PWHASH_OPSLIMIT_INTERACTIVE` / `SODIUM_CRYPTO_PWHASH_MEMLIMIT_INTERACTIVE` (64 MiB) and ceiling `2 * SODIUM_CRYPTO_PWHASH_OPSLIMIT_MODERATE` / `2 * SODIUM_CRYPTO_PWHASH_MEMLIMIT_MODERATE` (512 MiB, fixed `2×` multiple of default; [PHP `sodium_crypto_pwhash`](https://www.php.net/manual/en/function.sodium-crypto-pwhash.php); [PHP Sodium Constants](https://www.php.net/manual/en/sodium.constants.php); [libsodium Argon2 `pwhash`](https://doc.libsodium.org/password_hashing/default_phf)). Before calling `sodium_crypto_pwhash()` and with **zero writes**, restore **refuses** any bundle whose `alg !== SODIUM_CRYPTO_PWHASH_ALG_ARGON2ID13` or whose `opslimit` or `memlimit` is below that floor or above that ceiling (`T18`); host memory feasibility for `MODERATE` / `2× MODERATE` across target PHP installations is **UNKNOWN** (gated by build-time memory test). Encrypt the entire bundle (signing public key, encryption keys, key IDs and format) using **`XChaCha20-Poly1305-IETF` AEAD** ([PHP `sodium_crypto_aead_xchacha20poly1305_ietf_encrypt`](https://www.php.net/manual/en/function.sodium-crypto-aead-xchacha20poly1305-ietf-encrypt.php); [libsodium AEAD](https://doc.libsodium.org/secret-key_cryptography/aead)) with a **fresh 24-byte (192-bit) random nonce** per bundle, binding cleartext version, salt, `alg`, bounded `opslimit`/`memlimit` and nonce as AEAD additional data. Nonce reuse is prevented both because every bundle derives a fresh key from a fresh salt (one encryption per key) and because `XChaCha20-Poly1305-IETF`'s 192-bit nonce permits random generation without practical collision limits ([libsodium AEAD](https://doc.libsodium.org/secret-key_cryptography/aead)); short-nonce AEAD modes with random nonces are disallowed, and any future multi-message AEAD under one key must use a strict monotonic counter or rekeying. Verify bundle AEAD authentication before trusting any metadata or signing key; wrong phrase, altered metadata/ciphertext or failed authentication rejects the bundle and restore without substituting any archive key. Securely deliver and test the bundle/phrase off-host; no phrase or key in logs. |
| Backup | Per backup generate a fresh random 256-bit data key, seal it to the encryption public key, and encrypt the archive with `crypto_secretstream_xchacha20poly1305` chunks requiring `TAG_FINAL` and no trailing bytes. **Stream nonce strategy:** `secretstream` generates a fresh 24-byte header per stream on `init_push` and manages its own internal per-chunk nonces/counters and rekeying, preventing nonce reuse, chunk reordering, duplication or truncation ([PHP `secretstream_init_push`](https://www.php.net/manual/en/function.sodium-crypto-secretstream-xchacha20poly1305-init-push.php); [libsodium `secretstream`](https://doc.libsodium.org/secret-key_cryptography/secretstream); [libsodium AEAD](https://doc.libsodium.org/secret-key_cryptography/aead)). Hash the exact canonical versioned header plus ciphertext incrementally with SHA-256; sign a domain-separated header+digest using Ed25519 detached signature over ciphertext, not a whole archive in memory ([sealed box](https://www.php.net/manual/en/function.sodium-crypto-box-seal.php) gives confidentiality/integrity, not sender identity; [sign](https://www.php.net/manual/en/function.sodium-crypto-sign-detached.php); [verify](https://www.php.net/manual/en/function.sodium-crypto-sign-verify-detached.php)). |
| Restore | Manager supplies independently trusted bundle and phrase. Validate cleartext bundle header format, `alg === SODIUM_CRYPTO_PWHASH_ALG_ARGON2ID13`, and `opslimit`/`memlimit` floor and ceiling (`Setup` above; `T18`) **before** invoking `sodium_crypto_pwhash()`, refusing out-of-range parameters with zero writes; derive wrapping key and verify bundle AEAD authentication before trusting any metadata or signing public key. Verify detached Ed25519 signature over the `0600` private archive copy (§5) with the bundle's signing public key before decrypting; never trust an embedded signing key. Unwrap data key and authenticate every chunk, `TAG_FINAL` and manifest/digests on both Pass 1 and Pass 2. Require sodium at both ends; absent extension = fail closed, no plaintext fallback. |
| Lifecycle | Create local encrypted output directly; do not write decrypted SQL or another plaintext dump file to disk. During restore feed authenticated chunks from memory directly into the existing empty target CPMS tables under the closed barrier (no staging tables); attachments use private temporary files as specified in §5. LIMITATION: database and private attachment storage may contain plaintext identity data; deletion of files on SSDs, snapshots, swap, DB logs and backups is not guaranteed. Protect these at least as strongly as the live site; disable application/driver query-parameter logging for restore and exclude identity values from restore logs, errors and reports. Database-managed journals and host snapshots remain subject to the live-site protection and retention policy. Reuse secretstream concepts from existing envelope (`src/Infrastructure/Backup/BackupEncryptionEnvelope.php:69-85`) but migrate S3 to mirror the same signed encrypted container, not a host-key-encrypted plaintext local backup. Legacy import requires separate explicitly approved migration and old key; no silent downgrade. |
| Loss and rotation | Loss of bundle or phrase makes protected private key unavailable unless separately secured recovery copies exist. Loss of signing public key prevents trusted verification; loss of signing secret prevents new signatures, not old verification. Rotate keys with explicit manager enrollment and new bundle; retain prior bundles to read historical backups. Losing only the host must not lose the doctor's backup and bundle. Live-host compromise can forge future signatures; show signed sequence/time and request manager confirmation against independent records. Anti-rollback is manual, not automatic. |

## 5. Restore, barrier, audit and rollback

| Phase | Required behavior |
|---|---|
| Preflight & lock | Fresh independent WP + compatible CPMS install, no clinical data and no conflicting CPMS users beyond a designated recovery manager; reject collisions, unsupported prefix, multisite or incompatible schema/engines. **Definition of "zero writes" (before-barrier guarantee):** zero changes to database rows, `wp_users`/`wp_usermeta`, `{prefix}cpms_*` tables, `wp_options` (including any durable barrier, journal or plugin option), and clinical uploads/private data roots (`clinic-files`, `cpms-backups`); the **ONLY** pre-barrier filesystem effect (in `restoreApply` only) is inside `PrivateStorageLocation::path('cpms-restore-staging')`: creating/verifying that `0700` directory (where host allows; [PHP `mkdir`](https://www.php.net/manual/en/function.mkdir.php), [PHP `chmod`](https://www.php.net/manual/en/function.chmod.php)), its fixed `0600` ownership marker `.cpms-restore-staging-owner`, and that attempt's single `0600` `restore-archive-<random_hex>.part` copy. **Proven staging exclusivity & ownership marker (M2):** OBSERVED: `files.storage_path` and `backup.storage_path` can override `PrivateStorageLocation` defaults (`clinic-practice-management/src/Infrastructure/Storage/PrivateStorageLocation.php:30-32,36-63,85-95`; `src/Bootstrap/App.php:1816-1820,2319-2325`; `src/Application/Backup/BackupService.php:465-511`; `src/Infrastructure/Storage/LocalFileStorage.php:65-80`; `src/Infrastructure/Backup/ProtectedBackupStore.php:85-100`), and a default private root can be shared across installs. Before any copy **and** before any sweep, after `clearstatcache(true)`, `cpms-restore-staging` must pass `assertOutsideWebRoot()`, be a real non-symlink directory (`is_link() === false`, `lstat()`), resolve via `realpath()` ([PHP `realpath`](https://www.php.net/manual/en/function.realpath.php)) — checked on its nearest existing ancestor **before** `mkdir()` and on the directory itself after — to a canonical path **neither equal to, inside, nor containing** the canonical path (existing path or nearest existing ancestor, cf. `src/Application/Backup/BackupS3MirrorRecovery.php:712-762`) of **any** default, legacy or configured `clinic-files` or `cpms-backups` root (otherwise refuse closed-vocabulary `STAGING_ROOT_OVERLAP_OR_UNSAFE` before creating any file), **and** hold the fixed regular non-symlink ownership marker `.cpms-restore-staging-owner` (`0600`, created by `restoreApply` via exclusive `fopen(..., 'xb')` **only** after the `realpath()` non-overlap check passes and **only** when `cpms-restore-staging` is newly created or completely empty, containing this install's canonical `<= 64`-char `GET_LOCK` identifier derived from `(realpath(ABSPATH), DB_HOST, DB_NAME, $wpdb->prefix)`; if the directory is non-empty without `.cpms-restore-staging-owner` or its marker does not match this install's lock identifier, refuse closed-vocabulary `STAGING_OWNERSHIP_MISMATCH` without creating, altering or deleting any file;
